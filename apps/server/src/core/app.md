# Server composition

`createApp` accepts `resolveGym`, `session`, and `authorize` so the application
boundary can be tested without a database. Resolution must populate
`context.gym`; session loading must set the principal before calling `next`.
Contributions mount through `createServerRegistry` with the resolved gym's
enabled modules. The default `app` blocks all gym surfaces until these slots
are connected.

Request IDs are generated by the server. Install liveness (`/healthz`) and
source metadata (`/api/source`, plus `/source` as a redirect) do not require a
gym. Public setup contracts with the `uninitialized_install` gate and the shipped
pack catalog (`/api/content-packs/catalog`) also mount before tenancy. Setup
handlers must enforce their install-local first-boot guard and become unavailable
after initialization; setup-owner routes still require tenancy and a session.
The install requires `X-Setup-Token` on public setup actions and restore polling;
`GET /api/setup` remains open. The token comes from the installer's private link.
Assets and the SPA load before tenancy so an empty install can open `/setup`.
OpenAPI (`/api/openapi.json`) runs after tenancy and session loading.
Browser navigation to `/admin`, `/portal`, `/kiosk`, `/login`, `/setup`, and `/demo`
receives the SPA index; missing API routes and asset files return the
standard JSON error envelope.

Pass `RestoreGate.middleware()` as `restoreGate` before tenant database access,
and use its activity leases for workers. Only setup restore initiation and status
polling bypass that middleware: the coordinator must begin outside the lease it
drains. Other first-boot handlers, the catalog, assets and gym routes use the gate.
Liveness and source metadata remain reachable while restore runs.

## Transport security

With `strictTransportSecurity` set (production only), responses for the
canonical host carry `Strict-Transport-Security: max-age=31536000` when its
origin is `https:`, without `includeSubDomains` or `preload`: a gym's hostname is
often a subdomain of a domain its owner uses for other services. The canonical
origin is a resolved gym's `origin`; requests that resolve no gym (install
endpoints, unknown hostnames) use a static `origin`, else `installOrigin`. Any
other hostname, an `http:` origin, or a missing origin gets no header, and
development leaves the option off so a browser never pins a local hostname. The header comes from the app rather than the Caddyfile, so
installs receive it with an image update.

## Content-Security-Policy reports

Responses that set no policy of their own carry `frame-ancestors 'none'` and a
report-only policy that names `POST /csp-report` (`report-to` with a
`Reporting-Endpoints` header, and `report-uri` for older browsers). The route
(`csp-report.ts`) is public and mounts before tenancy, so it needs no gym, session
or CSRF Origin; it stores nothing and never echoes a body. It reads
`application/reports+json` and `application/csp-report` bodies up to 16 KiB (a larger
one gets the usual 400 from the body limit) and logs one `csp.violation` line per
report, up to five per request, holding only the format, the effective directive
(a known name or `other`), the blocked resource's origin, scheme (`data:`) or keyword
(`inline`), and the document's path. In that path a signed link's token becomes
`/l/:token` and every segment that is not one of the app's own route words (`admin`,
`members`, `invoices`, ...) becomes `:id`, so IDs, tokens and names never appear; the
query, fragment, host, samples, referrers, source files and the raw body are never
logged. Any other body or content type is ignored. Each client may send 30 requests a
minute and the install 300; requests over either budget are dropped unlogged. Every
request within the body cap and the budgets answers 204, so a browser has nothing to
retry and a flood nothing to react to.

Set `origin` to the canonical install origin or a function of the resolved gym;
it defaults to the request URL's origin, never forwarded host/protocol headers.
Cookie-authenticated writes require a matching Origin and reject cross-site
Fetch Metadata. The exact Stripe webhook path is exempt because its handler
verifies the signature. A kiosk exemption requires an authenticated same-gym
kiosk principal, a bearer header, and a kiosk API path.
Set `installOrigin` to the install's canonical origin for first-boot writes,
which have no resolved gym. These requests have a separate install/client IP
rate-limit bucket and never call a gym-dependent origin function.

Rate limiting defaults to 300 requests per minute per gym and client key,
with at most 10,000 in-memory buckets per process. `clientKey` keeps an IPv4
address as it is, counts an IPv4-mapped IPv6 address as IPv4, and groups other
IPv6 addresses by /64, as Better Auth's limiter does; every limiter uses it. A
full table (`RateBuckets`) evicts rather than refusing new clients, so a flood
can't lock new visitors out: ended windows and the oldest buckets still within
their limits go first, and a bucket over its limit goes only once every other
bucket is too, so lifting a refusal takes a flood that fills the whole table
with refused clients. Refusals keep their
`Retry-After`. This is process-local flood protection; auth
retains its database-backed limiter. `peerAddress` defaults to the Node socket
address. Set `trustedProxy` to a predicate matching only the immediate reverse
proxy; only then is the rightmost X-Forwarded-For address used. Pass the same
`clientIp` helper and proxy options to the auth binding.

`SOURCE_URL` is read when constructing the app, defaults to the public source
repository, and is passed through Docker and Compose. Footers can use `/source`
or load `/api/source` to follow a runtime override. Existing SPA footers use
their build-time URL until connected to this endpoint.

The install endpoint schemas are declared locally. TODO: move these declarations
into the shared contracts, which currently omit these endpoints. All four
endpoints explicitly declare public access with the same `route` helper used
by area routes, and appear in the generated OpenAPI document.

## Production composition

`core/runtime.ts` builds the running server: `startRuntime()` checks
`APP_ENCRYPTION_KEY`, `AUTH_SECRET`, and the public origin, initializes the
database, and passes the real tenant resolver, session middleware, `authorize`,
and restore gate to `createApp`. It also starts the jobs worker (paused while a
restore holds the install, with each job inside a restore-gate lease), schedules
backups once they are configured, and configures signed-link email and the
login methods each gym offers. `index.ts` serves that app, or runs a `gym-app`
command when started with arguments (`deploy/container/gym-app.sh`).
Kiosk authentication wraps session loading. Demo startup verifies environment and
stored Stripe keys, routes every email to the outbox, disables setup and uploads,
mounts entry/creation before tenancy, and schedules cleanup behind the restore gate.

The public origin is `PUBLIC_ORIGIN`, or `https://` plus `GYM_HOSTNAME`, in
single mode; in multi mode it is the hostname the tenant resolver matched.
`TRUST_PROXY=true` (set in Compose, where only Caddy reaches the app) makes the
last `X-Forwarded-For` entry the client address for rate limits and login.
`RATE_LIMIT_PER_MINUTE` (an integer from 1 to 100,000) replaces the flood limit's
default of 300 requests per minute per gym and client address; route limiters and
the auth limiter keep their own limits.
